# Запуск на другом ПК с Windows и VS Code

1. Установите Node.js 24 и Git for Windows. VS Code сам по себе их не устанавливает.
2. Скачайте репозиторий GitHub через Code → Download ZIP и распакуйте либо выполните git clone с адресом репозитория.
3. В VS Code выберите «Файл → Открыть папку» и откройте папку, где находится package.json.
4. Откройте «Терминал → Создать терминал» и выполните:

~~~powershell
node --version
npm.cmd ci
npm.cmd run dev
~~~

Откройте http://127.0.0.1:5173. При первом запуске настройки .env создаются автоматически, PostgreSQL запускается локально, схема базы обновляется. При пустой базе создайте KEYUSER через форму первоначальной настройки. Отдельно устанавливать PostgreSQL для стандартного локального запуска не требуется.

npm.cmd работает и при ограничениях PowerShell на запуск npm.ps1. Для установки зависимостей нужен доступ в Интернет. Если корпоративная политика запрещает запуск встроенной PostgreSQL, используйте согласованную с ИТ внешнюю PostgreSQL и задайте DATABASE_URL в локальном .env.

## Каждый следующий запуск

В терминале папки проекта:

~~~powershell
npm.cmd run dev
~~~

Остановка — Ctrl+C. Данные сохраняются в .postgres. Не удаляйте эту папку.

## Обновление из GitHub

Если проект получен через git clone, остановите приложение, затем:

~~~powershell
git pull --ff-only
npm.cmd ci
npm.cmd run dev
~~~

## Рабочие данные

GitHub хранит исходный код. Локальные .env, .postgres, резервные копии, пароли и зависимости не загружаются в репозиторий. На новом ПК создаётся отдельная база. Для переноса имеющихся смесей, измерений и пользователей используйте отдельную резервную копию по инструкции DEPLOYMENT.md. Не добавляйте её в GitHub. Две локальные установки не синхронизируют данные через Git: для общей работы подключайте обе к одному серверу приложения/базы данных.
